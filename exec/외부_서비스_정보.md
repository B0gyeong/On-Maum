## 1. 인증 — Keycloak (자체 호스팅)

외부 가입이 필요 없는 자체 호스팅 서비스입니다. EC2-A에 컨테이너로 띄웁니다.

- 이미지: `quay.io/keycloak/keycloak:26.4`
- 접속 도메인: `AUTH_DOMAIN` (운영 `https://nilm-auth.duckdns.org`)
- Realm import 파일: `infrastructure/keycloak/nilm-realm.json`
  - Realm `nilm`, 자체 회원가입 비활성(`registrationAllowed: false`)
  - Realm Role: `USER`, `ADMIN`, `STAFF`
  - Client
    | Client ID | 종류 | 용도 | 필요한 값 |
    |---|---|---|---|
    | `nilm-dashboard` | public, Authorization Code + PKCE(S256) | 프론트엔드 | `FRONTEND_ORIGIN` (redirect URI) |
    | `nilm-backend` | confidential, service account + password grant | iot-device-service의 회원가입(Admin API)·로그인 | `NILM_BACKEND_CLIENT_SECRET` |
    | `nilm-smoke` | confidential, service account | 배포 후 HTTP 검증 스크립트 | `NILM_SMOKE_CLIENT_SECRET` |
- 관리자 계정: `KEYCLOAK_ADMIN` / `KEYCLOAK_ADMIN_PASSWORD` (`keycloak_db`가 비어 있을 때 한 번만 생성)
- 백엔드 설정 키: `KEYCLOAK_SERVER_URL`, `KEYCLOAK_REALM`, `KEYCLOAK_BACKEND_CLIENT_ID`, `NILM_BACKEND_CLIENT_SECRET`, `JWT_ISSUER_URI`
- 프론트엔드는 Keycloak에 직접 접속하지 않고 `/api/auth/login`(iot-device-service)을 거쳐 로그인합니다.
- 참고 문서: `docs/배포설정/Keycloak_운영환경_설정.md`

### 소셜 인증
사용하지 않습니다. Realm에 Identity Provider가 없고 코드에도 소셜 로그인 연동이 없습니다.

## 2. 푸시 알림 — Web Push (VAPID)

브라우저 표준 Web Push를 사용합니다. Firebase(FCM) 같은 별도 계정은 필요 없고, VAPID 키 쌍만 직접 생성하면 됩니다.

- 라이브러리: `nl.martijndwars:web-push:5.1.1` (monitoring-service)
- 키 생성 예시
  ```bash
  npx web-push generate-vapid-keys
  ```
- 설정 키
  | 위치 | 키 | 설명 |
  |---|---|---|
  | monitoring-service | `WEB_PUSH_ENABLED` | Web Push 사용 여부 |
  | monitoring-service | `WEB_PUSH_VAPID_PUBLIC_KEY` / `WEB_PUSH_VAPID_PRIVATE_KEY` | VAPID 키 쌍 |
  | monitoring-service | `WEB_PUSH_SUBJECT` | 연락처(`mailto:...` 또는 URL) |
  | 프론트엔드 빌드 | `VITE_WEB_PUSH_VAPID_PUBLIC_KEY` | 백엔드와 같은 공개키 (Jenkins `frontend-build-env`) |
- HTTPS 환경에서만 동작하며, 대상자 브라우저에서 알림 권한을 허용해야 합니다.

## 4. CI/CD — Jenkins

- 파이프라인: 루트 `Jenkinsfile`
- 에이전트 라벨: `ci`(빌드), `ec2-a`, `ec2-b`(배포)
- Credential (ID만 기재, 값은 Jenkins에 저장)
  | ID | 종류 | 내용 |
  |---|---|---|
  | `registry-login` | Username/Password | Docker Hub 계정 + Access Token |
  | `ec2-a-runtime-env` | Secret file | EC2-A용 `.env` |
  | `ec2-b-runtime-env` | Secret file | EC2-B용 `.env` |
  | `frontend-build-env` | Secret file | 프론트엔드 빌드용 Vite 환경 파일 |
  | `discord-webhook` | Secret text | Discord 알림 Webhook URL |
- 참고 문서: `docs/배포설정/Jenkins_실행_및_검증.md`

## 7. 서버·도메인·인증서

### AWS EC2 (SSAFY 제공)
| 서버 | 역할 |
|---|---|
| EC2-A (Edge / Service) | Nginx(프론트엔드), API Gateway, 기기 인증, 모니터링, Keycloak, Mosquitto, Redis, Prometheus, Grafana |
| EC2-B (Stream / Data) | PostgreSQL, Kafka, 실시간 패턴 분석, 집계 배치, MQTT-Kafka Bridge, HDFS, Bronze·세션 적재, node-exporter |

- 두 서버는 같은 VPC이며, EC2-A 서비스는 `POSTGRES_HOST`, `EC2_B_PRIVATE_IP`로 EC2-B에 접속합니다.
- SSH 키: `J15D201T.pem` (SSAFY 제공, 저장소에 없음)
- 아키텍처 그림의 S3 Data Lake는 현재 코드에 접속 설정(버킷·리전 환경변수, SDK)이 없고, 데이터 레이크는 HDFS를 사용합니다.

### 도메인
| 용도 | 도메인 | 발급처 |
|---|---|---|
| 서비스 (`APP_DOMAIN`, `FRONTEND_ORIGIN`) | `j15d201.p.ssafy.io` | SSAFY 제공 |
| 인증 (`AUTH_DOMAIN`, `KEYCLOAK_HOSTNAME`) | `nilm-auth.duckdns.org` | DuckDNS (계정 생성 후 서브도메인 등록, EC2-A 공인 IP 연결) |

### Let's Encrypt (certbot)
- 두 도메인을 하나의 인증서로 발급합니다.
  ```bash
  sudo certbot certonly --standalone -d j15d201.p.ssafy.io -d nilm-auth.duckdns.org
  ```
- 발급된 `fullchain.pem`, `privkey.pem`을 `/opt/nilm/certs/`에 둡니다. 자동 갱신은 설정되어 있지 않으므로 만료 전에 다시 발급합니다.
- MQTT(8883) TLS는 Let's Encrypt가 아닌 **자체 사설 CA**(`CN=nilm-mqtt-ca`)로 발급합니다. 참고: `docs/배포설정/MQTT_인증서_및_계정_준비.md`

## 9. AI 학습 — SSAFY GPU 서버

## 10. CDN — jsDelivr

- 프론트엔드 폰트(SUIT, Pretendard): `frontend/index.html`, `frontend/src/styles/global.css`
- Chart.js: 모니터링 보고서 템플릿, 시뮬레이터 페이지
- 가입 불필요. 사용자 브라우저에서 인터넷 접속이 필요합니다.

## 11. 사용하지 않는 외부 서비스

| 서비스 | 비고 |

| 소셜 로그인 (Google, Kakao, Naver 등) | Keycloak 자체 계정만 사용 |
| 포톤 클라우드 (Photon) | 해당 없음 |
| Firebase / FCM | 표준 Web Push(VAPID) 사용 |
| 문자(SMS)·전화 API | 전화번호는 저장만 하고, 전화는 기기의 `tel:` 링크로 연결 |
| 이메일(SMTP) | Keycloak SMTP 미설정 |
| 지도 API | 위치 서비스는 브라우저 `navigator.geolocation`만 사용 |
| LLM API (OpenAI, Gemini 등) | 해당 없음 |
| Mattermost / Slack | 알림은 Discord 사용 |
| Sentry, Cloudflare, ngrok | 해당 없음 |
