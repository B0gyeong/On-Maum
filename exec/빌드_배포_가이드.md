| JVM 옵션 (monitoring) | `-Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8` | `backend/monitoring-service/Dockerfile` |

| 서비스 | 포트 | WAS | 주요 의존성 |
|---|---|---|---|
| api-gateway | 8080 (`SERVER_PORT`) | **Netty** (Spring Cloud Gateway WebFlux) | gateway-server-webflux, oauth2-resource-server, actuator |
| iot-device-service | 8081 | **내장 Tomcat** | web, data-jpa, Flyway, spring-kafka, Paho MQTTv5 1.2.5, springdoc 2.8.9, PostgreSQL |
| monitoring-service | 8082 | **내장 Tomcat** | web, thymeleaf, data-jpa, data-redis, Flyway, spring-kafka, web-push 5.1.1, bcprov 1.84, springdoc 2.8.9 |

주요 설정 (`src/main/resources/application.properties`, 프로필 분리 없음)
- Gateway 라우팅: `/api/devices/**`, `/api/auth/**` → device / `/api/monitoring/stream`(SSE, `response-timeout=-1`), `/api/monitoring/**` → monitoring
- JPA `ddl-auto=none`, `open-in-view=false`, 스키마는 Flyway가 관리 (device V1~V10, monitoring V1~V19)
- Kafka Producer `acks=all`, idempotence 사용 / monitoring Consumer 수동 ack(`ack-mode=record`)
- 보안 `app.security.enabled` 기본값: gateway·device `false`, monitoring `true` (운영은 모두 켬)
- JWT issuer 기본값 `http://localhost:8090/realms/nilm`, 운영은 JWK Set URI를 `http://keycloak:8080/...`로 지정
- Actuator `health`, `info` 노출, readiness 그룹에 db(·kafkaListeners) 포함

- 빌드: `npm ci` → `npm run lint && npm run build`(`tsc -b && vite build`). Vite 환경 파일은 BuildKit secret으로 `/app/.env.production`에 주입
- 로컬 이미지 Nginx(`frontend/nginx.conf`): 80 포트, `/healthz`, `/api/` → `api-gateway:8080`(`proxy_buffering off`, `proxy_read_timeout 3600s`), SPA fallback
- 운영 Nginx: 별도 컨테이너 없이 **프론트엔드 이미지가 엣지 리버스 프록시** 역할. `infrastructure/nginx/default.conf.template`을 덮어씀
  - 80 → 443 리다이렉트, TLSv1.2/1.3, 인증서 `/etc/nginx/certs/fullchain.pem`, `privkey.pem`
  - `${APP_DOMAIN}`: 정적 파일 + `/api/` → api-gateway, `/simulator/`는 Basic 인증
  - `${AUTH_DOMAIN}`: `keycloak:8080` 프록시(X-Forwarded 헤더)

인증서 발급
```bash
# Let's Encrypt (EC2-A, 80 포트 비운 상태)
sudo certbot certonly --standalone -d <APP_DOMAIN> -d <AUTH_DOMAIN>

# MQTT 사설 CA (EC2-A)
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 -keyout ca.key -out ca.crt -subj "/CN=nilm-mqtt-ca"
openssl req -newkey rsa:2048 -nodes -keyout server.key -out server.csr -subj "/CN=nilm-mqtt"
printf "subjectAltName=IP:<EC2_A_PRIVATE_IP>\nextendedKeyUsage=serverAuth\n" > san.cnf
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -days 3650 -out server.crt -extfile san.cnf

# MQTT 계정 (첫 계정만 -c, 이후 계정은 -c 없이)
sudo docker run --rm -it -v /opt/nilm/mqtt:/work eclipse-mosquitto:2 mosquitto_passwd -c /work/passwd kafka_bridge_user
```

### 3.6 배포 특이사항

**배포 조건**
- `master` 브랜치만 배포합니다. 다른 브랜치를 같은 서버에 배포하면 Flyway 순서가 꼬입니다.
- ci·EC2-A·EC2-B의 Docker 아키텍처가 같아야 합니다(단일 플랫폼 빌드, 불일치 시 배포 중단).
- 중간 스테이지부터 재시작할 수 없습니다(stash 미보존). 처음부터 다시 실행합니다.

**최초 기동 때 고정되는 값** (`.env`만 바꿔서는 반영되지 않음)
| 값 | 변경 방법 |
|---|---|
| `POSTGRES_USER`, `POSTGRES_PASSWORD` | `ALTER ROLE` 실행 후 `.env` 수정 |
| `KEYCLOAK_ADMIN_PASSWORD` | Keycloak 콘솔 또는 `kcadm.sh set-password` |
| `FRONTEND_ORIGIN`, `NILM_SMOKE_CLIENT_SECRET`, `NILM_BACKEND_CLIENT_SECRET` | realm import 때만 반영 → Keycloak 콘솔에서 수정 |
| `MQTT_USER`, `MQTT_PASS` | 실제 인증은 passwd 파일 → `mosquitto_passwd`로 갱신 |
| `GRAFANA_ADMIN_PASSWORD` | Grafana DB 최초 생성 때만 적용 |
| `KAFKA_CLUSTER_ID` | 포맷된 볼륨과 일치해야 하므로 변경 금지 |

**서버 간 반드시 일치해야 하는 값**
- EC2-A·EC2-B의 `POSTGRES_USER`, `POSTGRES_PASSWORD`
- EC2-A `POSTGRES_HOST` = EC2-B `EC2_B_PRIVATE_IP`
- Bridge `MQTT_HOST` = MQTT 서버 인증서 SAN
- `JWT_ISSUER_URI` = `<KEYCLOAK_HOSTNAME>/realms/nilm`
- `WEB_PUSH_VAPID_PUBLIC_KEY` = `VITE_WEB_PUSH_VAPID_PUBLIC_KEY`
- 집계 `ROUTINE_BASELINE_*` = Gold `GOLD_PROFILE_*`

**DB 마이그레이션**
- PostgreSQL 초기화 SQL은 데이터 디렉터리가 비었을 때만 실행됩니다. DB를 추가하려면 수동 `CREATE DATABASE`가 필요합니다.
- Flyway(device, monitoring)는 Spring 기동 시 자동 적용합니다. **이미 배포된 `V*.sql`은 수정 금지**(체크섬 불일치로 기동 실패). 변경은 새 버전 파일로 추가합니다.
- Alembic(`analysis_db`)은 실시간 분석 컨테이너 시작 시 `alembic upgrade head`로 적용되며, 나머지 Python 서비스는 분석 서비스가 healthy가 된 뒤 뜹니다.
- Kafka 토픽 자동 생성이 꺼져 있어 모든 토픽은 `kafka-init`이 만듭니다(파티션 변경·삭제는 하지 않음).
- Keycloak realm import는 `nilm` realm이 없을 때만 실행되고 기존 realm을 덮어쓰지 않습니다.

**최초 배포 후 수동 작업**
1. 세션 레이크 초기 적재(1회): `docker compose run --rm --no-deps session-lake-loader session-lake-loader initial-load`
2. Gold 일일 배치 타이머 등록
   ```bash
   sudo install -m 600 /opt/nilm/gold-daily.env.example /opt/nilm/gold-daily.env
   sudo /opt/nilm/bin/install-gold-daily-systemd.sh '*-*-* 06:30:00 Asia/Seoul'
   sudo systemctl enable --now gold-profile-daily.timer
   ```
3. (선택) 보고서: `reporting_schema.sql`을 `monitoring_db`에 적용, `grafana_reporting` 계정 생성, `REPORT_DATABASE_URL`·`GRAFANA_REPORTING_*` 설정, `HOUSEHOLD_REPORT_ENABLED=true`
4. (선택) 시뮬레이터: `ec2-a-runtime-env`에 `SIMULATOR_MQTT_HOST`·`SIMULATOR_MQTT_PASS` 추가, CA·htpasswd·passwd 준비 후
   `cd /opt/nilm && docker compose --profile simulator up -d simulator` → `https://<APP_DOMAIN>/simulator/routine-demo`
5. 테스트 계정은 `TEST_DATA_ENABLED=true`면 monitoring-service가 기동할 때 자동 생성합니다. 끄고 운영하면 Keycloak 콘솔(`https://<AUTH_DOMAIN>/admin/`)에서 직접 생성합니다(자체 회원가입 비활성).

**운영 기본값 주의**
- EC2-B 분석 서비스 기본 `ANALYSIS_MODEL_BACKEND=fake`입니다. 실제 모델 추론은 `real`로 지정합니다.
- HDFS 보존 정책은 `RETENTION_APPLY=true`로 바꾸기 전까지 dry-run입니다.
- Gold 프로필 전달은 종단 검증 후 `GOLD_PROFILE_DELIVERY_MODE=ACTIVE`로 올립니다(기본 `SHADOW`).
- `GRAFANA_REPORTING_DB_HOST` 기본값 `localhost:5432`는 EC2-A에서 틀린 값이므로 EC2-B 주소로 지정합니다.
- Let's Encrypt 자동 갱신이 없으므로 만료 전에 재발급 후 frontend 컨테이너를 재시작합니다.
- MQTT 인증서 교체 후에는 `docker compose --project-directory /opt/nilm restart mosquitto`가 필요합니다(HUP로는 부족).
- 운영에서 **`docker compose down -v` 금지** (DB, Kafka, HDFS 볼륨 삭제).

**롤백 (수동)**
1. 이전 `/opt/nilm/last-success.json`과 `/opt/nilm/releases/<RELEASE_ID>/previous/` 백업을 확인
2. 해당 digest를 pull
3. EC2-B 기반 → EC2-A → EC2-B 분석 → Bridge 순서로 재기동

**로컬 환경 주의**
- 저장소 경로에 한글·공백이 있으면 OpenSSL이 CA 파일을 읽지 못합니다. `ca.crt`는 `C:\nilm\ca.crt` 같은 ASCII 경로에 둡니다.
- 새로 clone한 경우 `infrastructure/mqtt/config/acl.device`가 없어 로컬 Mosquitto가 실패할 수 있습니다. 공용 계정 ACL(`simulator_user` write `v1/power/sim/#`, `kafka_bridge_user` read `v1/power/sim/#`, `v1/device/#`)로 직접 만듭니다.
- 프론트엔드 컨테이너(3000)로 로그인하면 realm의 `FRONTEND_ORIGIN`이 `http://localhost:5173`이라 redirect 오류가 날 수 있습니다. 로컬 로그인은 Vite 개발 서버(5173)에서 합니다.
- 백엔드 이미지 빌드는 테스트를 포함하므로, 테스트 실패 시 `docker compose build <서비스> --progress=plain`으로 로그를 확인합니다.

## 4. DB 접속 정보·주요 계정·프로퍼티 정의 파일

### 4.1 데이터베이스 (PostgreSQL 18, EC2-B `${EC2_B_PRIVATE_IP}:5432`)

`infrastructure/postgres/01-create-databases.sql`이 최초 기동 때 DB 4개를 만듭니다. 계정은 모든 서비스가 `POSTGRES_USER`(기본 `nilm_admin`) / `POSTGRES_PASSWORD` 하나를 함께 씁니다.

| DB | 사용 서비스 | 접속 설정 위치 | 스키마 관리 |
|---|---|---|---|
| `device_db` | iot-device-service | `backend/iot-device-service/src/main/resources/application.properties` (`POSTGRES_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`) | Flyway `db/migration/V1~V10` |
| `monitoring_db` | monitoring-service | `backend/monitoring-service/src/main/resources/application.properties` (`POSTGRES_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, 보고서용 `DEMO_REPORT_DB_*`) | Flyway `db/migration/V1~V19` |
| `analysis_db` | 실시간 분석, 집계·Silver·Gold 배치, 세션 레이크 적재 | 환경변수 `DATABASE_HOST/PORT/NAME/USER/PASSWORD` → `ai/realtime-analysis-service/src/realtime_analysis/database.py`에서 URL 조립 | Alembic `ai/realtime-analysis-service/alembic/versions` |
| `keycloak_db` | Keycloak | `KC_DB_URL`, `KC_DB_USERNAME`, `KC_DB_PASSWORD` (`infrastructure/ec2-a/compose.yaml`) | Keycloak 자체 관리 |
| `monitoring_db.reporting` 스키마 | Gold 배치 보고서, Grafana | `REPORT_DATABASE_URL`, `GRAFANA_REPORTING_DB_*` / DDL `batch/gold_profile_service/reporting_schema.sql` | 수동 적용 (`batch/gold_profile_service/REPORTING.md`) |

- 읽기 전용 계정 `grafana_reporting`은 `REPORTING.md`의 GRANT SQL로 수동 생성합니다.
- `exec/` 폴더에 `device_db.dump`, `monitoring_db.dump`, `analysis_db.dump`가 있으면 `pg_restore`로 복원해 시연 데이터를 그대로 쓸 수 있습니다.
