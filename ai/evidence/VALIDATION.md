# R3 로컬 자산·추가 범위·데모 검수 (2026-09-21)

구현 검증: 6개 선정 장면의 실제 모델 및 MQTT → Kafka → 분석 PostgreSQL →
monitoring PostgreSQL → HTTP 조회 완료. 모델 일반화/안전 판단 승인과는 별개다.
체크포인트/정규화/문턱을 수정하지 않았다. 아래 모든 새 추론은 CPU float32, batch 1,
thread 1이며 기준 출력은 H200 BF16이다.

## 추가 18개 대조군

원본 패널은 기존 로컬 R2 검토 패키지에서 가져왔고 각 config의 SHA256과 일치함을 확인한 후
별도 프로세스에서 실제 forward했다. 정답/기준 출력은 종료 후 평가에서만 읽었다.
긴 prefix 6개 모두 선정 구간 점수/상태가 cold 실행과 정확히 같다. 확장된 주변 구간에는
인덕션 미탐 4초, 전자레인지 미탐 5초·오탐 1초, 청소기 오탐 5초가 있다.

| 가전 | OFF 600초 중 오탐 | 다른 날짜 recall | 다른 날짜 오탐 | 다른 날짜 H200 상태 차이 |
|---|---:|---:|---:|---:|
| 전기포트 | 43초 | 41.22% | 0초 | 1초 |
| 인덕션 | 0초 | 95.57% | 3초 | 0초 |
| 다리미 | 2초 | 91.18% | 6초 | 0초 |

따라서 미선정 날짜/상황에 대한 일반화 성공으로 판정하지 않는다. CPU/H200 상태 차이는

긴 prefix 및 OFF 대조군에서는 H200 상태 차이가 없다.

## 범위 및 재현

`broker-six-scenes/summary.json`: 6회 실제 MQTT·Kafka·PG·API 기록.
`local-six-scenes-v2/summary.json`: 새 프로세스 12회 추론 비교.
`local-controls/summary.json`: 18개 대조군 성능과 drift.
전체 JSONL은 로컬에 남기되 Git에서는 제외한다. 재생성 명령은
`infrastructure/r3-demo/README.md`와 `ai/tools/`에 있다. 프론트엔드 catalog에는 run 식별자와
검수 메타데이터만 있고 예상 확률/정답은 없다. 새 DB에서는 실제 MQTT runner를 먼저 실행한다.

24개 원래 검수 항목 중 이번 추가 실행은 T02/T03/T06–T09/T11–T16/T19/T23을 확대했다.
T05/T10/T17/T18/T21은 기존 단위·내구성 시험으로 유지한다. 기존 kettle 재시작/중복
실제 broker 시험을 모든 모델에 반복한 것은 아니다. 1Hz 벽시계 지연 부하 시험,
운영 알림/외출 규칙 통합, 운영 컷오버 및 일반화 성능 승인은 이번 결과에 포함하지 않는다.
monitoring 표준 Dockerfile 전체 빌드는 이전과 같이 미완료이며 현재 실행 이미지는
동일 소스의 검증된 bootJar 런타임 이미지다. 이미지/DB 볼륨 삭제나 원격 push는 수행하지 않는다.
